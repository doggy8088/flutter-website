給 JavaScript 開發者（ES6）的 Dart 入門

#

和 React Native 類似，Flutter 採用反應式（reactive-style）視圖。不過，RN 會轉譯成原生元件（Widgets），而 Flutter 則是直接編譯為原生程式碼。Flutter 能夠控制螢幕上的每一個像素，因此不需要 JavaScript 橋接層，能夠避免由此產生的效能問題。

Dart 是一個容易學習的語言，具備以下特點：

  • 提供一個開源、可擴展的程式語言，可用於開發 Web、伺服器及行動應用程式。
  • 採用物件導向、單一繼承，並使用類似 C 語法，能夠 AOT 編譯成原生程式碼。
  • 可選擇性地轉譯（transcompile）成 JavaScript。
  • 支援介面（interface）與抽象類別（abstract class）。

以下簡單說明 JavaScript 與 Dart 之間的一些差異。

Futures

#

與 JavaScript 類似，Dart 支援單執行緒（single-threaded）執行。在 JavaScript 中， Promise 物件代表非同步操作最終完成（或失敗）及其結果值。

Dart 則使用 Future 物件來處理這類情境。

js
// JavaScript
class Example {
  _getIPAddress() {
    const url = 'https://httpbin.org/ip';
    return fetch(url)
      .then(response => response.json())
      .then(responseJson => {
        const ip = responseJson.origin;
        return ip;
      });
  }
}

function main() {
  const example = new Example();
  example
    ._getIPAddress()
    .then(ip => console.log(ip))
    .catch(error => console.error(error));
}

main();
dart
// Dart
import 'dart:convert';

import 'package:http/http.dart' as http;

class Example {
  Future<String> _getIPAddress() {
    final url = Uri.https('httpbin.org', '/ip');
    return http.get(url).then((response) {
      final ip = jsonDecode(response.body)['origin'] as String;
      return ip;
    });
  }
}

void main() {
  final example = Example();
  example
      ._getIPAddress()
      .then((ip) => print(ip))
      .catchError((error) => print(error));
}

async 與 await

#

async 函式宣告用於定義非同步函式。

在 JavaScript 中，async 函式會回傳一個 Promise。 await 運算子則用來等待 Promise。

js
// JavaScript
class Example {
  async function _getIPAddress() {
    const url = 'https://httpbin.org/ip';
    const response = await fetch(url);
    const json = await response.json();
    const data = json.origin;
    return data;
  }
}

async function main() {
  const example = new Example();
  try {
    const ip = await example._getIPAddress();
    console.log(ip);
  } catch (error) {
    console.error(error);
  }
}

main();

在 Dart 中，async 函式會回傳 Future，而該函式的主體會被排程於之後執行。 await 運算子用於等待 Future。

dart
// Dart
import 'dart:convert';

import 'package:http/http.dart' as http;

class Example {
  Future<String> _getIPAddress() async {
    final url = Uri.https('httpbin.org', '/ip');
    final response = await http.get(url);
    final ip = jsonDecode(response.body)['origin'] as String;
    return ip;
  }
}

/// An async function returns a `Future`.
/// It can also return `void`, unless you use
/// the `avoid_void_async` lint. In that case,
/// return `Future<void>`.
void main() async {
  final example = Example();
  try {
    final ip = await example._getIPAddress();
    print(ip);
  } catch (error) {
    print(error);
  }
}

我該如何使用元件並將其巢狀組合成元件樹（widget tree）？

#

在 Flutter 中，幾乎所有東西都是元件（Widget）。

元件是應用程式使用者介面的基本構建區塊。 你可以將元件組合成一個階層結構，這稱為元件樹（widget tree）。 每個元件都巢狀於其父元件之內，並從父元件繼承屬性。 甚至連應用程式物件本身也是一個元件。 這裡沒有獨立的「application」物件。 相反地，根元件（root widget）扮演了這個角色。

一個元件可以定義：

  • 結構性元素——例如按鈕或選單
  • 樣式元素——例如字型或配色方案
  • 版面配置的某個面向——例如內距（padding）或對齊（alignment）

以下範例展示了使用 Material 函式庫元件的「Hello world!」應用程式。在這個例子中，元件樹巢狀於MaterialApp根元件之中。

dart
// Flutter
import 'package:flutter/material.dart';

void main() => runApp(const MyApp());

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Welcome to Flutter',
      home: Scaffold(
        appBar: AppBar(title: const Text('Welcome to Flutter')),
        body: const Center(child: Text('Hello world')),
      ),
    );
  }
}

以下圖片展示了由 Material Design 元件 (Widgets) 所構建的 "Hello world!" 範例。 你可以發現，這個版本比最基本的 "Hello world!" 應用程式提供了更多的功能。

在撰寫應用程式時，你會使用兩種類型的元件 (Widgets)： StatelessWidget 或 StatefulWidget。 StatelessWidget 顧名思義，就是沒有狀態的元件 (Widget)。 StatelessWidget 只會被建立一次，外觀永遠不會改變。 StatefulWidget 則會根據接收到的資料或使用者輸入，動態地改變其狀態。

無狀態元件 (stateless widgets) 和有狀態元件 (stateful widgets) 之間最重要的差異在於， StatefulWidget 會有一個 State 物件來儲存狀態資料， 並在元件樹重建時保留這些資料，因此不會遺失。

在簡單或基礎的應用程式中，巢狀元件 (Widgets) 很容易管理； 但隨著程式碼基礎擴大、應用程式變得複雜時， 你應該將巢狀過深的元件拆分為回傳元件的函式或更小的類別。 建立獨立的函式與元件 (Widgets) 可以讓你在應用程式內重複使用這些元件。

如何建立可重複使用的元件 (Components)？

#

在 React Native 中，你會定義一個函式（或類別）來建立可重複使用的元件 (Component)， 然後使用 props 方法來設定或回傳所選元素的屬性和值。 在下方範例中，定義了一個 CustomCard 函式，並在父元件 (Parent Component) 中使用它。

js
// React Native
const CustomCard = ({ index, onPress }) => {
  return (
    <View>
      <Text> Card {index} </Text>
      <Button
        title="Press"
        onPress={() => onPress(index)}
      />
    </View>
  );
};

// Usage
<CustomCard onPress={this.onPress} index={item.key} />

在 Flutter 中，您可以定義一個類別來建立自訂元件（Widget），然後重複使用該元件。您也可以像下方範例中的 build 函式一樣，定義並呼叫一個會回傳可重複使用元件的函式。

dart
/// Flutter
class CustomCard extends StatelessWidget {
  const CustomCard({super.key, required this.index, required this.onPress});

  final int index;
  final void Function() onPress;

  @override
  Widget build(BuildContext context) {
    return Card(
      child: Column(
        children: <Widget>[
          Text('Card $index'),
          TextButton(onPressed: onPress, child: const Text('Press')),
        ],
      ),
    );
  }
}

class UseCard extends StatelessWidget {
  const UseCard({super.key, required this.index});

  final int index;

  @override
  Widget build(BuildContext context) {
    /// Usage
    return CustomCard(
      index: index,
      onPress: () {
        print('Card $index');
      },
    );
  }
}

在前一個範例中，CustomCard 類別的建構函式使用 Dart 的大括號語法 { } 來表示具名參數。

若要強制這些欄位為必填，可以移除建構函式中的大括號，或是在建構函式中加入 required。

我要將資源和 Assets 放在哪裡？要怎麼使用？

#

在 Flutter 中，資源（resource）或 Assets（資源）是與應用程式一起打包並部署的檔案，這些檔案可在執行時存取。Flutter 應用程式可以包含以下類型的資源：

  • 靜態資料，例如 JSON 檔案
  • 設定檔
  • 圖示與圖片（JPEG、PNG、GIF、動畫 GIF、WebP、動畫 WebP、BMP 和 WBMP）

Flutter 會使用位於專案根目錄下的 pubspec.yaml 檔案來識別應用程式所需的資源。

yaml
flutter:
  assets:
    - assets/my_icon.png
    - assets/background.png

assets 子區段指定了應與應用程式一同包含的檔案。 每個資源（asset）都以相對於 pubspec.yaml 檔案的明確路徑來識別，也就是該資源檔案所在的位置。 宣告資源的順序沒有影響。 實際使用的目錄（本例中為 assets）也沒有影響。 然而，雖然資源可以放在應用程式的任何目錄中，最佳實踐是將它們放在 assets 目錄下。

在建置過程中，Flutter 會將資源放入一個特殊的歸檔檔案，稱為 asset bundle（資源包），應用程式在執行時會從中讀取資源。 當資源的路徑被指定在 pubspec.yaml 的 assets 區段時，建置流程會尋找相鄰子目錄中任何同名的檔案。 這些檔案也會與指定的資源一同包含進資源包中。Flutter 在為您的應用程式選擇適合解析度的圖片時，會使用資源變體（asset variants）。

在 React Native 中，您會將靜態圖片檔案放在原始碼目錄中，並直接引用它。

js
<Image source={require('./my-icon.png')} />
// OR
<Image
  source={{
    url: 'https://reactnative.dev/img/tiny_logo.png'
  }}
/>

在 Flutter 中，您可以在元件（Widget）的 build 方法中，使用 Image.asset 建構函式，將靜態圖片加入您的應用程式。

dart
Image.asset('assets/background.png');

如需更多資訊，請參閱 Adding Assets and Images in Flutter。

元件通常由許多小型、單一用途的元件組成，並以巢狀方式產生強大的效果。例如，Container 元件由多個負責版面配置、繪製、定位和尺寸調整的元件組成。具體來說，Container 元件包含 LimitedBox、ConstrainedBox、Align、Padding、DecoratedBox 以及 Transform 元件。你不需要透過繼承 Container 來產生自訂效果，而是可以將這些及其他簡單元件以全新且獨特的方式組合。

狀態管理

#

狀態（State）是指在元件（Widget）建立時可同步讀取的資訊，或是在元件生命週期內可能會改變的資訊。要在 Flutter 中管理應用程式狀態，請使用 StatefulWidget 搭配 State 物件。

如需更多關於在 Flutter 中管理狀態的方法，請參考 State management。

StatelessWidget（無狀態元件）

#

Flutter 中的 StatelessWidget 是一種不需要狀態變化的元件（Widget）——它本身沒有需要管理的內部狀態。

當你要描述的使用者介面部分僅依賴於物件本身的組態資訊，以及該元件被建立時的 BuildContext，而不需要依賴其他狀態時，無狀態元件（StatelessWidget）就非常實用。

AboutDialog、CircleAvatar 和 Text 都是繼承自 StatelessWidget 的無狀態元件（stateless widgets）範例。

dart
import 'package:flutter/material.dart';

void main() => runApp(
  const MyStatelessWidget(
    text: 'StatelessWidget Example to show immutable data',
  ),
);

class MyStatelessWidget extends StatelessWidget {
  const MyStatelessWidget({super.key, required this.text});

  final String text;

  @override
  Widget build(BuildContext context) {
    return Center(child: Text(text, textDirection: TextDirection.ltr));
  }
}

前一個範例使用 MyStatelessWidget 類別的建構函式來傳遞 text，該參數被標記為 final。 這個類別繼承自 StatelessWidget——它包含不可變的資料。

無狀態元件 (StatelessWidget) 的 build 方法通常只會在三種情況下被呼叫：

  • 當元件（Widget）被插入到樹中時
  • 當元件的父元件變更其組態時
  • 當其所依賴的 InheritedWidget 發生變化時

StatefulWidget

#

StatefulWidget 是一個會改變狀態的元件（Widget）。 請使用 setState 方法來管理 StatefulWidget 的狀態變化。 呼叫 setState() 會通知 Flutter 框架某個狀態已發生變化， 這會導致應用程式重新執行 build() 方法， 以便讓應用程式反映這個變化。

State（狀態）是指在元件（Widget）建立時可以同步讀取，且在元件生命週期內可能會改變的資訊。 元件實作者有責任確保當狀態變更時，狀態物件能夠及時收到通知。 當元件（Widget）會動態變化時，請使用 StatefulWidget。 例如，透過在表單中輸入文字或移動滑桿，元件的狀態會改變。 又或者，狀態也可能隨時間變化——例如資料來源更新 UI。

Checkbox、Radio、Slider、InkWell、 Form 和 TextField 都是繼承自 StatefulWidget 的 stateful 元件（stateful widgets）範例。

下列範例宣告了一個 StatefulWidget， 它需要一個 createState() 方法。 此方法會建立管理元件狀態的狀態物件， 也就是 _MyStatefulWidgetState。

dart
class MyStatefulWidget extends StatefulWidget {
  const MyStatefulWidget({super.key, required this.title});

  final String title;

  @override
  State<MyStatefulWidget> createState() => _MyStatefulWidgetState();
}

以下這個狀態類別 _MyStatefulWidgetState，為該元件（Widget）實作了 build() 方法。 當狀態改變時，例如使用者切換按鈕時，會以新的切換值呼叫 setState()。 這會導致框架重新建立（rebuild）此元件於 UI 上。

dart
class _MyStatefulWidgetState extends State<MyStatefulWidget> {
  bool showText = true;
  bool toggleState = true;
  Timer? t2;

  void toggleBlinkState() {
    setState(() {
      toggleState = !toggleState;
    });
    if (!toggleState) {
      t2 = Timer.periodic(const Duration(milliseconds: 1000), (t) {
        toggleShowText();
      });
    } else {
      t2?.cancel();
    }
  }

  void toggleShowText() {
    setState(() {
      showText = !showText;
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: Center(
        child: Column(
          children: <Widget>[
            if (showText)
              const Text('This execution will be done before you can blink.'),
            Padding(
              padding: const EdgeInsets.only(top: 70),
              child: ElevatedButton(
                onPressed: toggleBlinkState,
                child: toggleState
                    ? const Text('Blink')
                    : const Text('Stop Blinking'),
              ),
            ),
          ],
        ),
      ),
    );
  }
}

StatefulWidget 與 StatelessWidget 的最佳實踐是什麼？

#

在設計元件（Widget）時，請考慮以下幾點：

  1. 判斷元件應該是 StatefulWidget 還是 StatelessWidget。

在 Flutter 中，元件（Widget）分為 Stateful 或 Stateless，這取決於它是否依賴狀態變化。

  • 如果元件會改變——例如使用者與其互動，或資料流導致 UI 中斷，那麼它就是 Stateful。
  • 如果元件是最終的（final）或不可變的（immutable），那麼它就是 Stateless。
  1. 判斷哪個物件管理元件的狀態（針對 StatefulWidget）。

在 Flutter 中，主要有三種方式來管理狀態：

  • 元件自己管理自己的狀態
  • 父元件管理子元件的狀態
  • 混合搭配的方式

在決定使用哪種方式時，請考慮以下原則：

  • 如果該狀態屬於使用者資料，例如核取方塊的勾選或未勾選狀態，或滑桿的位置，那麼由父元件管理狀態會比較合適。
  • 如果該狀態屬於美觀（aesthetic），例如動畫（Animation），那麼由元件自己管理狀態會比較合適。
  • 如果不確定，建議讓父元件管理子元件的狀態。
  1. 繼承 StatefulWidget 與 State。

MyStatefulWidget 類別會自行管理狀態——它繼承自 StatefulWidget，並覆寫 createState() 方法來建立 State 物件，框架會呼叫 createState() 來建構元件。 在此範例中，createState() 會建立 _MyStatefulWidgetState 的實例，該實作會在下一個最佳實踐中介紹。

dart
class MyStatefulWidget extends StatefulWidget {
  const MyStatefulWidget({super.key, required this.title});

  final String title;
  @override
  State<MyStatefulWidget> createState() => _MyStatefulWidgetState();
}

class _MyStatefulWidgetState extends State<MyStatefulWidget> {
  @override
  Widget build(BuildContext context) {
    //...
  }
}
  1. 將 StatefulWidget 加入元件樹（Widget tree）。

在應用程式的 build 方法中，將你自訂的 StatefulWidget 加入元件樹（Widget tree）。

dart
class MyStatelessWidget extends StatelessWidget {
  // This widget is the root of your application.
  const MyStatelessWidget({super.key});

  @override
  Widget build(BuildContext context) {
    return const MaterialApp(
      title: 'Flutter Demo',
      home: MyStatefulWidget(title: 'State Change Demo'),
    );
  }
}

如何儲存全域且持久化的 key-value 對？

#

在 React Native 中，你可以使用 AsyncStorage 元件的 setItem 與 getItem 函數，來儲存與讀取全域且持久化於應用程式中的資料。

js
// React Native
const [counter, setCounter] = useState(0)
...
await AsyncStorage.setItem( 'counterkey', json.stringify(++this.state.counter));
AsyncStorage.getItem('counterkey').then(value => {
  if (value != null) {
    setCounter(value);
  }
});

在 Flutter 中，請使用 shared_preferences 套件來儲存與讀取應用程式全域且持久化的鍵值資料。shared_preferences 套件在 iOS 上包裝了 NSUserDefaults，在 Android 上則包裝了 SharedPreferences，為簡單資料提供持久化儲存功能。

若要將 shared_preferences 套件加入為相依套件，請執行 flutter pub add：

flutter pub add shared_preferences
dart
import 'package:shared_preferences/shared_preferences.dart';

要實作持久性資料，請使用 SharedPreferences 類別所提供的 setter 方法。

setter 方法可用於多種基本型別，例如 setInt、setBool 和 setString。

若要讀取資料，請使用 SharedPreferences 類別所提供的適當 getter 方法。

每個 setter 都有對應的 getter 方法，例如 getInt、getBool 和 getString。

dart
Future<void> updateCounter() async {
  final prefs = await SharedPreferences.getInstance();
  int? counter = prefs.getInt('counter');
  if (counter is int) {
    await prefs.setInt('counter', ++counter);
  }
  setState(() {
    _counter = counter;
  });
}

路由（Routing）

#

大多數應用程式都包含多個螢幕，用來顯示不同類型的資訊。例如，你可能有一個商品螢幕（product screen），用來顯示圖片，使用者可以點擊某個商品圖片，在新的螢幕上查看更多關於該商品的資訊。

在 Android 中，每個新螢幕對應一個新的 Activity。 在 iOS 中，每個新螢幕對應一個新的 ViewController。而在 Flutter 中，螢幕就是元件（Widgets）！要在 Flutter 中導覽到新的螢幕，可以使用 Navigator 元件（Navigator widget）。

如何在螢幕之間進行導覽？

#

在 React Native 中，主要有三種導覽器（navigator）：StackNavigator、TabNavigator 和 DrawerNavigator。 每一種都提供設定與定義螢幕的方式。

js
// React Native
const MyApp = TabNavigator(
  { Home: { screen: HomeScreen }, Notifications: { screen: tabNavScreen } },
  { tabBarOptions: { activeTintColor: '#e91e63' } }
);
const SimpleApp = StackNavigator({
  Home: { screen: MyApp },
  stackScreen: { screen: StackScreen }
});
export default (MyApp1 = DrawerNavigator({
  Home: {
    screen: SimpleApp
  },
  Screen2: {
    screen: drawerScreen
  }
}));

在 Flutter 中，有兩個主要的元件（Widgets）用於在螢幕之間導覽：

  • Route 是對應用程式螢幕或頁面的抽象。
  • Navigator 是一個管理路由（Route）的元件（Widget）。

Navigator 被定義為一個以堆疊（stack）方式管理一組子元件（child widgets）的元件。Navigator 會管理一個 Route 物件的堆疊，並提供管理該堆疊的方法，例如 Navigator.push 和 Navigator.pop。 路由（routes）清單可以在 MaterialApp 元件中指定，或者也可以動態建立，例如在 hero 動畫（animation）中。 以下範例在 MaterialApp 元件中指定了命名路由（named routes）。

分頁（Tab）導覽

#

在 React Native 中，createBottomTabNavigator 和 TabNavigation 用於顯示分頁以及進行分頁導覽。

js

Flutter 提供了多種專門用於抽屜（drawer）和分頁（tab）導覽的元件（Widgets）：

TabController
協調 TabBar 和 TabBarView 之間的分頁選擇。
TabBar
顯示一個水平排列的分頁列。
Tab
建立一個 Material Design 風格的 TabBar 分頁。
TabBarView
顯示對應於目前所選分頁的元件（Widget）。
dart
class _MyAppState extends State<MyApp> with SingleTickerProviderStateMixin {
  late TabController controller = TabController(length: 2, vsync: this);

  @override
  Widget build(BuildContext context) {
    return TabBar(
      controller: controller,
      tabs: const <Tab>[
        Tab(icon: Icon(Icons.person)),
        Tab(icon: Icon(Icons.email)),

    );

}

TabController 是用來協調 TabBar 與 TabBarView 之間的分頁（tab）選擇所必需的。 TabController 建構函式的 length 參數代表分頁的總數。 每當畫面（frame）觸發狀態變更時，必須有 TickerProvider 來觸發通知。 TickerProvider 是 vsync。每當你建立新的 TabController 時，請將 vsync: this 參數傳遞給 TabController 建構函式。

TickerProvider 是一個由能夠提供 Ticker 物件的類別所實作的介面。 Ticker 可被任何需要在每次畫面（frame）觸發時收到通知的物件使用，但最常見的是透過 AnimationController 間接使用。AnimationController 需要 TickerProvider 來取得它們的 Ticker。 如果你是從 State 建立 AnimationController，那麼你可以使用 TickerProviderStateMixin 或 SingleTickerProviderStateMixin 類別來取得合適的 TickerProvider。

Scaffold 元件（Widget）會包裹一個新的 TabBar 元件，並建立兩個分頁（tabs）。 TabBarView 元件會作為 Scaffold 元件的 body 參數傳入。 所有對應於 TabBar 元件分頁的螢幕（screens）都會作為 TabBarView 元件的子元件（children），並且共用相同的 TabController。

dart
class _NavigationHomePageState extends State<NavigationHomePage>
    with SingleTickerProviderStateMixin {
  late TabController controller = TabController(length: 2, vsync: this);

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      bottomNavigationBar: Material(
        color: Colors.blue,
        child: TabBar(
          tabs: const <Tab>[
            Tab(icon: Icon(Icons.person)),
            Tab(icon: Icon(Icons.email)),
          ],
          controller: controller,
        ),
      ),
      body: TabBarView(
        controller: controller,
        children: const <Widget>[HomeScreen(), TabScreen()],
      ),
    );
  }
}

為了偵測並回應手勢，Flutter 支援點擊（tap）、拖曳（drag）以及縮放（scaling）。Flutter 的手勢系統分為兩個獨立的層級。第一層包含原始指標事件（raw pointer events），這些事件描述指標（例如觸控、滑鼠、觸控筆等）在螢幕上的位置與移動。第二層則是手勢（gestures），用來描述語意上的動作，並且由一個或多個指標移動所組成。

如何為元件（Widget）新增點擊或按壓監聽器？

#

在 React Native 中，可以透過將監聽器加到元件上，使用 PanResponder 或 Touchable 元件來實現。

// React Native
const App = () => {

      <View style={styles.center}>
        <Text>Swipe Horizontally or Vertically</Text>

dart
import 'dart:io';

dart
final url = Uri.parse('https://httpbin.org/ip');
final httpClient = HttpClient();

Future<void> getIPAddress() async {
  final request = await httpClient.getUrl(url);
  final response = await request.close();
  final responseBody = await response.transform(utf8.decoder).join();

  });
}

#

在 Flutter 中，可以使用 Form 元件（Widget），並將 TextFormField 元件（Widgets）和提交按鈕作為 children 傳入。 TextFormField 元件有一個名為 onSaved 的參數，該參數接受一個 callback，並在表單被儲存時執行。FormState 物件可用於儲存、重設或驗證每一個作為此 Form 子孫的 FormField。 要取得 FormState，你可以使用 Form.of() 並傳入一個其祖先為 Form 的 context，或是在建立 Form 時傳入 GlobalKey，然後呼叫 GlobalKey.currentState()。

dart
@override

    key: formKey,
    child: Column(

          validator: (value) {
            if (value != null && value.contains('@')) {
              return null;
            }
            return 'Not a valid email.';
          },
          onSaved: (val) {
            _email = val;
          },
          decoration: const InputDecoration(
            hintText: 'Enter your email',
            labelText: 'Email',
          ),
        ),
        ElevatedButton(onPressed: _submit, child: const Text('Login')),
      ],
    ),
  );
}

void _submit() {

        return AlertDialog(
          title: const Text('Alert'),
          content: Text('Email: $_email, password: $_password'),

  }
}

動畫 (Animation)

#

精心設計的動畫能讓 UI 更直覺， 提升應用程式的質感， 並改善使用者體驗。 Flutter 的動畫 (Animation) 支援讓你輕鬆 實作簡單或複雜的動畫效果。 Flutter SDK（Flutter 軟體開發套件）內建許多 Material Design 元件 (Widgets)， 包含標準的動態效果， 你也能輕鬆自訂這些效果， 讓你的應用程式更具個人風格。

在 React Native 中，會使用 Animated API 來建立動畫。

在 Flutter 中，請使用 Animation 類別以及 AnimationController 類別。 Animation 是一個抽象類別，能掌握其 目前的值與狀態（已完成或已關閉）。 AnimationController 類別可讓你 向前或反向播放動畫， 或停止動畫並將動畫 設為特定值，以自訂動畫行為。

如何加入簡單的淡入動畫？

#

在下方的 React Native 範例中，會使用 Animated API 建立一個動畫元件， FadeInView。 定義了初始透明度狀態、最終狀態，以及動畫過渡的持續時間。 動畫元件會被加入到 Animated 元件內， 透明度狀態 fadeAnim 會對應到我們想要動畫的 Text 元件的 opacity 屬性， 然後呼叫 start() 來啟動動畫。

js
// React Native
const FadeInView = ({ style, children }) => {
  const fadeAnim = useRef(new Animated.Value(0)).current;

  useEffect(() => {
    Animated.timing(fadeAnim, {
      toValue: 1,
      duration: 10000
    }).start();
  }, []);

  return (
    <Animated.View style={{ ...style, opacity: fadeAnim }}>
      {children}
    </Animated.View>
  );
};
    ...
<FadeInView>
  <Text> Fading in </Text>
</FadeInView>
    ...

要在 Flutter 中建立相同的動畫，請建立一個名為 controller 的 AnimationController 物件，並指定持續時間。預設情況下，AnimationController 會在指定的持續時間內，線性產生從 0.0 到 1.0 的數值。每當執行您應用程式的裝置準備好顯示新畫面時，動畫控制器就會產生一個新數值。通常這個速率約為每秒 60 個數值。

在定義 AnimationController 時，您必須傳入一個 vsync 物件。vsync 的存在可以防止螢幕外的動畫消耗不必要的資源。您可以透過在類別定義中加入 TickerProviderStateMixin，將您的 stateful 物件作為 vsync 使用。AnimationController 需要一個 TickerProvider，這可以透過建構函式的 vsync 參數來設定。

Tween 描述了起始值與結束值之間的插值，或是從輸入範圍對應到輸出範圍的映射。若要將 Tween 物件用於動畫，請呼叫 Tween 物件的 animate() 方法，並傳入您想要修改的 Animation 物件。

在此範例中，使用 FadeTransition 元件，並將 opacity 屬性對應到 animation 物件。

若要啟動動畫，請使用 controller.forward()。您也可以透過控制器執行其他操作，例如 fling() 或 repeat()。

在本範例中，FlutterLogo 元件會被用在 FadeTransition 元件內。

dart
import 'package:flutter/material.dart';

void main() {
  runApp(const Center(child: LogoFade()));
}

class LogoFade extends StatefulWidget {
  const LogoFade({super.key});

  @override
  State<LogoFade> createState() => _LogoFadeState();
}

class _LogoFadeState extends State<LogoFade>
    with SingleTickerProviderStateMixin {
  late Animation<double> animation;
  late AnimationController controller;

  @override
  void initState() {
    super.initState();
    controller = AnimationController(
      duration: const Duration(milliseconds: 3000),
      vsync: this,
    );
    final CurvedAnimation curve = CurvedAnimation(
      parent: controller,
      curve: Curves.easeIn,
    );
    animation = Tween(begin: 0.0, end: 1.0).animate(curve);
    controller.forward();
  }

  @override
  void dispose() {
    controller.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return FadeTransition(
      opacity: animation,
      child: const SizedBox(height: 300, width: 300, child: FlutterLogo()),
    );
  }
}

如何為卡片加入滑動動畫（swipe animation）？

#

在 React Native 中，通常會使用 PanResponder 或第三方函式庫來實現滑動動畫（swipe animation）。

在 Flutter 中，若要加入滑動動畫，請使用 Dismissible 元件（Widget），並將子元件（child widgets）巢狀於其中。

dart
return Dismissible(
  key: Key(widget.key.toString()),
  onDismissed: (dismissDirection) {
    cards.removeLast();
  },
  child: Container(
    //...
  ),
);
